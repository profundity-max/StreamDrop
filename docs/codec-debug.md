# 首条视频只有声音：诊断与修复

2026-10-18，StreamDrop 1.0.2（build 3）。

## 已证实

- 受影响文件 `AI_Karpathy_-_5000_AI [UD8_5fhFayY].mp4` 含 VP9/vp09 1080p 视频与 AAC 音频，时长 515.691973 秒。FFmpeg 在 30 秒和 240 秒可解码实际图像，未发现下载遗漏整个视频流。
- 本机 AVFoundation 报无法解码（AVFoundation -11833，OSStatus -12906），AVAssetReader 无法启动、无画面。后续三个工作样本为 AV1，原生读取画面成功。因此问题为该文件与本机系统播放器的编码兼容性。
- 原件保留；新建同目录 `(兼容版).mp4`，视频 H.264/yuv420p，手动修复副本直接复制原 AAC 音轨。兼容副本 1920×1080、时长不变、56,364,977 字节，原生解码输出实际像素成功。
- 仅受影响 UUID 的任务和历史改为兼容副本路径与实际大小，其余成功任务未改。状态更改前备份在 `.test-output/codec-debug/state-before-compatible-repair.json`。

## 代码修复

默认兼容选项同分辨率优先 H.264/AAC。网页视频完成后由 NativeVideoProbe 统一判定原生画面解码；轨道存在但解码失败时转换为 H.264/AAC，转换后必须读到画面才成功。原始下载在独立工作目录保留至转换成功，失败时提供日志及具体原因。直链维持字节原样，关闭兼容选项时不转换；未知轨道/探测异常仍是未知，不视为已验证可播放。

多阶段启动与暂停/取消使用同一锁仲裁，复用 OwnedProcess 的进程组和排空机制。队列按 transfer 类型结算暂停：URLSession 等待独立恢复数据回调；网页终态失败立即按暂停意图结算、释放槽位，避免 pausing 卡住。按 Data 换行后解码 UTF-8，避免跨块中文日志损坏。
